คู่มือติดตั้ง Massage POS บน iPad เครื่องเดียว

คู่มือนี้ใช้กับรุ่น PWA เท่านั้น ไม่ต้องเปิด Windows หรือเครื่องเซิร์ฟเวอร์ไว้ในร้าน ตัวโปรแกรมดาวน์โหลดจากเว็บ HTTPS ส่วนการขาย คำนวณค่ามือ และเก็บข้อมูลทำใน iPad โดยตรง

repository ของคุณคือ actiara26/POS-NURU ใช้เก็บชุดโปรแกรม ส่วนเว็บติดตั้งใช้ Cloudflare Pages ไม่เปิด GitHub Pages สำหรับ POS ร้านจริง

ลิงก์ติดตั้งประจำร้าน: เปิด POS NURU · คู่มือฉบับเว็บ

สถานะ: โปรแกรมผ่านการทดสอบในเบราว์เซอร์แล้ว ต้องตรวจลิงก์เผยแพร่และทดสอบบน iPad เครื่องที่จะใช้จริงก่อนรับเงินจริง การทดสอบบนคอมพิวเตอร์ยังแทนการทดสอบ Safari บนเครื่องคุณไม่ได้

1. แยกของสองอย่างก่อน

- ไฟล์โปรแกรม: อยู่ในชุด ZIP สำหรับเผยแพร่ PWA มีหน้าจอและระบบทำงาน ไม่มีข้อมูลจริงของร้าน

- ข้อมูลร้าน: ชื่อพนักงาน บิล กะ ค่ามือ และบัญชีผู้ใช้ เก็บใน iPad ไฟล์สำรองลงท้าย .sqlite ต้องเก็บส่วนตัว ห้ามอัปโหลดเข้า repository สาธารณะ

GitHub ไม่ใช่ที่สำรองยอดขายของร้าน การที่เว็บยังอยู่ไม่ได้แปลว่าข้อมูลใน iPad กู้คืนได้ ถ้าเครื่องเสียต้องใช้ไฟล์สำรองที่ส่งออกไว้เอง

2. เตรียม iPad

1. ใช้ iPadOS 17 ขึ้นไป รุ่นนี้กำหนดให้ใช้ Safari และตรวจความสามารถเก็บข้อมูลก่อนเปิด POS

2. ต่ออินเทอร์เน็ตสำหรับการติดตั้งครั้งแรก ตั้งวัน เวลา และเขตเวลาให้ถูกต้อง เพราะใช้กำหนดวันทำการและเวลาบิล

3. ตั้งรหัสปลดล็อกเครื่อง และจำ PIN เจ้าของร้านไว้ในที่ส่วนตัว

4. เปิดแอป ไฟล์ (Files) เตรียมโฟลเดอร์ POS Backup ใน iCloud Drive หรืออุปกรณ์จัดเก็บภายนอก อย่าเก็บสำเนาเดียวไว้ใน “บน iPad ของฉัน”

5. เตรียมรายชื่อบริการ ราคา ระยะเวลา ค่ามือ พนักงาน ห้อง และเวลาเปิดร้าน ถ้ามีข้อมูล POS เดิม เตรียมไฟล์สำรอง .sqlite ที่สร้างจากเมนูสำรองของระบบเดิม

3. เก็บโปรแกรมใน GitHub และเผยแพร่ด้วย Cloudflare Pages

GitHub เก็บและติดตามรุ่นโปรแกรม ส่วน Cloudflare แจกไฟล์ติดตั้ง HTTPS ร้านไม่ต้องมีเซิร์ฟเวอร์และไม่ต้องเปิดคอมพิวเตอร์ค้าง โฮสต์ทั้งสองไม่ได้รับฐานข้อมูลร้านตามไปด้วย เลือกไม่ใช้ GitHub Pages เพราะมีข้อจำกัดเกี่ยวกับเว็บไซต์ที่มุ่งรองรับธุรกรรมเชิงพาณิชย์ ข้อจำกัด GitHub Pages

สำหรับผู้ดูแล: ทำขั้นตอนเผยแพร่จากคอมพิวเตอร์สะดวกที่สุด แต่หลังติดตั้งแล้วใช้ iPad เครื่องเดียวทำงานร้านได้

1. เก็บชุดโปรแกรมรุ่นล่าสุดใน repository actiara26/POS-NURU โดยไม่อัปโหลดข้อมูลจริง

2. เข้าบัญชี Cloudflare ของคุณ เปิด Workers & Pages → Create application → Pages → Direct Upload ชื่อปุ่มอาจเป็น Get started / Drag and drop your files ตามหน้าจอที่ Cloudflare แสดง

3. ตั้งชื่อโครงการร้านและเลือกอัปโหลดชุด ZIP สำหรับเผยแพร่ ภายใน ZIP ต้องมี index.html, sw.js และโฟลเดอร์ releases อยู่ระดับบนสุด ไม่ซ้อนโฟลเดอร์โครงการอีกชั้น

4. ตรวจว่าอัปโหลดครบ ไม่มีไฟล์ขึ้นผิดพลาด แล้วเลือก Deploy site / Save and Deploy

5. รอสถานะเผยแพร่สำเร็จ จด Production URL ที่ลงท้าย .pages.dev หรือโดเมนที่ตั้งไว้ ใช้ลิงก์นี้ต่อเนื่อง ไม่ติดตั้งจากลิงก์ Preview ที่เปลี่ยนทุกครั้ง

6. เปิด Production URL ตรวจว่ามีหน้าติดตั้ง/ตั้งเจ้าของและไม่มีข้อผิดพลาด จึงส่งลิงก์ให้ iPad ติดตั้ง

7. การเผยแพร่แบบ Direct Upload ต้องอัปโหลดรุ่นใหม่ที่ Cloudflare ด้วย การอัปโหลด GitHub อย่างเดียวจะไม่เปลี่ยนเว็บไซต์ และไม่ควรเปลี่ยนโครงการ/โดเมนภายหลังโดยไม่มีแผนย้ายข้อมูล

Cloudflare รองรับการอัปโหลด ZIP ทางหน้าจอสำหรับไฟล์ที่สร้างเสร็จแล้ว โดยไม่ต้องเชื่อมสิทธิ์ GitHub เพิ่มเติม คู่มือ Direct Upload

ใช้ลิงก์ HTTPS ที่เผยแพร่จริงติดตั้งใน iPad อย่าใช้หน้ารายการโค้ด github.com/..., ลิงก์ 127.0.0.1 หรือเปิดไฟล์ HTML จากแอปไฟล์

ไม่อัปโหลด data, .env, ไฟล์สำรอง .sqlite, ไฟล์ log, บัญชีผู้ใช้จริง หรือโฟลเดอร์โครงการทั้งหมด ชุด ZIP ที่จัดให้คัดเฉพาะไฟล์เผยแพร่แล้ว

4. ติดตั้งบนหน้าจอโฮม

1. บน iPad เปิด Safari ปกติ ไม่ใช้ Private Browsing

2. เปิด Production URL ของร้านจาก Cloudflare รอหน้าคำแนะนำติดตั้ง

3. กดปุ่ม แชร์ แล้วเลือก เพิ่มไปยังหน้าจอโฮม (Add to Home Screen)

4. ตั้งชื่อ Massage POS และเปิด Open as Web App / เปิดเป็นเว็บแอป หากเครื่องแสดงตัวเลือกนี้ แล้วกด เพิ่ม เมนูอาจต่างกันตามรุ่น iPadOS คู่มือ Apple

5. ปิดแท็บ Safari ของ POS กลับหน้าจอโฮม แล้วกดไอคอนที่เพิ่งเพิ่ม

6. รอให้เตรียมไฟล์ออฟไลน์และเปิดฐานข้อมูลเสร็จ ครั้งแรกต้องต่ออินเทอร์เน็ตจนเห็นหน้าตั้งบัญชีเจ้าของร้าน

7. เริ่มลงข้อมูลจากไอคอนนี้เท่านั้น ไม่สลับกรอกใน Safari, Chrome และไอคอนหลายชุด เพราะอาจอยู่คนละพื้นที่เก็บข้อมูล

ถ้าขึ้นว่าเปิดอยู่ในหน้าต่างอื่น ให้ปิดหน้าต่าง POS อื่น แล้วเปิดจากไอคอนเดียว ไม่แก้ด้วยการล้างข้อมูลเว็บไซต์

5. ตั้งเจ้าของร้านครั้งแรก

1. กรอกชื่อเจ้าของที่ต้องการให้ปรากฏในประวัติผู้ทำรายการ

2. ตั้ง PIN อย่างน้อย 6 หลัก ไม่ใช้เลขเรียงหรือเลขซ้ำทั้งหมด และพิมพ์ยืนยันให้ตรงกัน

3. กด ตั้งรหัสและเริ่มใช้งาน

4. เข้าแล้วจะเห็นข้อความ บันทึกข้อมูลในเครื่อง · ไฟล์ออฟไลน์พร้อม · รุ่น ...

PIN นี้เป็นของ POS ไม่ใช่รหัส Apple หรือ GitHub ไม่มีบริการส่งรหัสใหม่ทางอีเมลในรุ่นนี้ ต้องรักษา PIN เจ้าของให้ดี

6. ถ้าเริ่มร้านใหม่ ให้ลงข้อมูลตามลำดับนี้

ข้อมูลร้าน

เข้า ตั้งค่า → ข้อมูลร้าน กรอกชื่อร้าน สาขา ที่อยู่ เบอร์โทร และข้อมูลบนใบเสร็จ ตรวจชื่อบัญชีและหมายเลขรับเงินหากใช้ จากนั้นกำหนดเวลาเริ่มกะ 1, เริ่มกะ 2 และสิ้นสุดกะ 2 แล้วกด บันทึกข้อมูลร้าน เวลาเลิกกะ 2 เป็นจุดตัดวันทำการด้วย ร้านที่เลิกหลังเที่ยงคืนต้องตรวจวันทำการให้ตรง

บริการและราคา

เข้า ตั้งค่า → บริการ ตรวจรายการตั้งต้นทุกรายการก่อนใช้ ราคาเดิมเป็นข้อมูลตั้งต้น ไม่ใช่ราคาที่รับรองว่าเป็นของร้านคุณ

เพิ่มหรือแก้ไขชื่อบริการ หมวดหมู่ ระยะเวลา ราคาขาย ค่ามือ และจำนวนพนักงานที่ต้องใช้ เช่น “นวดไทย 60 นาที ราคา 350 บาท ค่ามือ 150 บาท ใช้พนักงาน 1 คน” เป็นเพียงตัวอย่าง ให้กรอกตามร้านจริง บริการที่ไม่ใช้ให้ปิดการใช้งาน

ห้อง

เข้า ผังห้อง ระบบมีโครงห้องตั้งต้น 10 ห้อง ให้แก้ชื่อ ประเภท และความจุให้ตรงร้าน เพิ่มห้องที่ขาดและซ่อนห้องที่ไม่ใช้ อย่าเริ่มขายโดยปล่อยชื่อหรือประเภทห้องที่ไม่ตรงของจริง

พนักงานนวด

เข้า พนักงานนวด → เพิ่มพนักงานนวด กรอกชื่อจริง ชื่อเล่น รหัสพนักงานตามที่หน้าจอกำหนด เบอร์โทรถ้าต้องการ และบันทึก เพิ่มให้ครบแล้วตรวจชื่อซ้ำ วันเปิดร้านให้เช็กอินเฉพาะคนที่มาทำงานจริง ไม่เช็กอินทุกคนโดยอัตโนมัติ

ผู้ใช้ระบบ

เข้า ตั้งค่า → ผู้ใช้งาน & สิทธิ์ เพิ่มบัญชีผู้จัดการและตั้ง PIN แยกจากเจ้าของ พนักงานนวดกับผู้ใช้ระบบเป็นคนละรายการ การเพิ่มหมอนวดไม่ได้แปลว่าได้สิทธิ์เข้า POS ด้วย

เมื่อกรอกครบ ให้สำรองและส่งออกหนึ่งชุดก่อนทดลองขาย ตั้งโฟลเดอร์สำเนาว่า “ก่อนเริ่มขายจริง”

7. ถ้ามีข้อมูล POS เดิม ให้ย้ายด้วยไฟล์สำรอง

ไฟล์ Excel, PDF, รูปถ่าย หรือรายงาน Google Sheets นำมากู้คืนทั้งระบบโดยตรงไม่ได้ รุ่นนี้รับไฟล์ฐานข้อมูล POS .sqlite หรือ .db ที่มีโครงสร้างถูกต้องและขนาดไม่เกิน 256 MB

1. ที่ POS เดิม ปิดกะและตรวจว่าทุกรายการบันทึกเรียบร้อย ใช้เมนูสำรองข้อมูลสร้างไฟล์ใหม่ อย่าคัดลอก pos.sqlite ขณะที่ระบบเดิมยังเขียนอยู่ เพราะอาจขาดข้อมูลที่อยู่ใน journal

2. ส่งไฟล์ไปยังพื้นที่ส่วนตัวที่เปิดจากแอปไฟล์บน iPad ได้ เช่น iCloud Drive ห้ามวางใน GitHub สาธารณะ

3. บน iPad ใหม่ ตั้งเจ้าของชั่วคราวตามหัวข้อ 5 เพื่อเข้าสู่เมนูนำเข้าได้ก่อน

4. เข้า ตั้งค่า → สำรองฐานข้อมูล → เลือกไฟล์สำรองจากแอปไฟล์ แล้วเลือกไฟล์ที่เตรียมไว้

5. ระบบตรวจไฟล์และเพิ่มในรายการสำรอง ขั้นตอนนี้ ยังไม่แทนที่ข้อมูลปัจจุบัน ชื่อไฟล์ในรายการจะเปลี่ยนเป็นรหัสใหม่ ให้ดูรายการล่าสุดและเวลานำเข้า

6. ตรวจว่าเลือกถูกไฟล์ แล้วกด กู้คืน อ่านข้อความยืนยัน การกู้คืนจะแทนที่ข้อมูลปัจจุบันทั้งหมด ไม่ใช่รวมสองร้านเข้าด้วยกัน ระบบจะสำรองข้อมูลก่อนกู้คืนอีกชุด

7. เมื่อกู้คืนสำเร็จ เข้าสู่ระบบด้วย PIN ที่อยู่ในข้อมูลเดิม บัญชีเจ้าของชั่วคราวอาจไม่มีแล้ว ถ้าเป็นสำเนาที่ลบบัญชีผู้ใช้ไว้ ระบบจะให้ตั้งเจ้าของใหม่

8. ตรวจชื่อร้าน จำนวนพนักงาน บริการ ห้อง บิลล่าสุด ยอดรายงาน และค่ามือค้างจ่ายเทียบกับระบบเดิม หากไฟล์มีกะเปิดค้าง ต้องจัดการกะนั้นตามความจริงก่อนเปิดกะใหม่

9. ส่งออกสำรองจาก iPad อีกครั้ง เมื่อย้ายสำเร็จให้ใช้ iPad เป็นเครื่องขายเพียงเครื่องเดียว ไม่ขายต่อพร้อมกันบนเครื่องเดิม เพราะรุ่นนี้ไม่ซิงก์สองเครื่อง

หากระบบบอกว่าไฟล์ใหม่เกินกว่ารุ่นที่รองรับหรือข้อมูลเสียหาย ให้หยุดและใช้ไฟล์ที่ถูกต้อง ห้ามเปลี่ยนนามสกุลหรือแก้เลขเวอร์ชันในไฟล์เพื่อบังคับนำเข้า

8. ทดสอบก่อนวันเปิดขายจริง

ทำหลังลงข้อมูลครบ แต่ยังไม่รับเงินจริง เก็บไฟล์ “ก่อนเริ่มขายจริง” ไว้นอกเครื่องก่อนเสมอ

1. ปิดแอปจากตัวสลับแอป เปิดโหมดเครื่องบินและปิด Wi-Fi ด้วย แล้วเปิด POS จากไอคอนอีกครั้ง

2. เข้าด้วย PIN ตรวจว่ารายชื่อและข้อมูลร้านยังอยู่

3. เปิดกะทดสอบ ระบุเงินสดตั้งต้นให้ชัด เช็กอินพนักงานหนึ่งคน

4. เปิดบิลทดสอบหนึ่งรายการ ตรวจราคาบริการ ค่ามือ ห้อง วิธีชำระ และยอดที่ยืนยัน

5. ปิดแล้วเปิดแอปใหม่ ตรวจ ประวัติบิล ว่ามีบิลเดียว หากมีแถบ ตรวจผลรายการเดิม ให้ตรวจรายการนั้นก่อน ห้ามเปิดบิลใหม่ซ้ำเพราะคิดว่าของเดิมหาย

6. จบบริการ จ่ายค่ามือของงานนั้น และปิดกะทดสอบ ตรวจว่าเงินสดตั้งต้น + รับเงินสด − จ่ายเงินสด ตรงเงินสดปิดกะ

7. ต่ออินเทอร์เน็ตอีกครั้ง ทดสอบดาวน์โหลดสำรอง เปิดแอปไฟล์และตรวจว่ามีไฟล์จริง ขนาดไม่เป็น 0 และซิงก์ไปนอกเครื่องแล้ว

8. ก่อนเริ่มขายจริง กู้คืนไฟล์ “ก่อนเริ่มขายจริง” เพื่อลบผลการทดลองทั้งชุด แล้วตรวจข้อมูลร้านใหม่ ขั้นตอนนี้ทำได้เฉพาะเมื่อยังไม่มีการขายจริงหลังไฟล์สำรองนั้น หากเริ่มขายจริงแล้วห้ามย้อนทั้งฐานเพื่อลบบิลทดลอง

9. ถ้าจะพิมพ์ใบเสร็จ ทดสอบกับเครื่องพิมพ์จริงด้วย รุ่น PWA ใช้หน้าพิมพ์ของ Safari/AirPrint ไม่รับรองว่าเครื่องพิมพ์ Bluetooth ทุกรุ่นจะใช้ได้

ถ้าข้อใดไม่ผ่าน ยังไม่ควรใช้รับเงินจริง จดข้อความผิดพลาดและส่งให้ผู้พัฒนา ไม่ล้างข้อมูลเว็บไซต์เพื่อเริ่มใหม่

9. การใช้ประจำวันและสำรองข้อมูล

เริ่มวัน: เปิดจากไอคอน → เข้าสู่ระบบ → ตรวจวันที่/กะ → เปิดกะและนับเงินตั้งต้น → เช็กอินพนักงานจริง → เริ่มขาย

ปิดวัน: จบบิลค้าง → ตรวจและจ่ายค่ามือตามจริง → นับเงินสด → ปิดกะ → เข้าด้วยเจ้าของ → ตั้งค่า → สำรองฐานข้อมูล → ตรวจสำเนาล่าสุด → ส่งออก

หลังส่งออก เปิดแอป ไฟล์ → ดาวน์โหลด หรือตำแหน่งดาวน์โหลดที่ตั้งไว้ ตรวจชื่อและขนาดไฟล์ แล้วคัดลอกไป iCloud Drive/POS Backup/ปี-เดือน-วัน หรืออุปกรณ์ภายนอก ตรวจว่าสถานะอัปโหลดเสร็จก่อนถือว่ามีสำเนานอกเครื่อง การกดปุ่มดาวน์โหลดเพียงอย่างเดียวยังไม่ใช่หลักฐานว่าไฟล์อยู่ใน iCloud แล้ว

สำเนาในตัว POS มีจำนวนจำกัด โดยปกติเก็บล่าสุดประมาณ 30 ชุด และเก็บสำเนาที่จำเป็นต่อการกู้คืนค้างเพิ่มเติม การนำเข้าและสำรองก่อนอัปเดตก็นับเป็นชุดสำรอง อย่าใช้รายการใน POS แทนคลังสำรองระยะยาว

iPad ขอพื้นที่เก็บแบบถาวรจากระบบได้ แต่ Safari/iPadOS เป็นผู้ตัดสินใจ ไม่ใช่การรับประกันว่าจะไม่มีวันถูกล้าง รุ่นนี้แจ้งเมื่อยังไม่ได้สิทธิ์ดังกล่าว นโยบายพื้นที่จัดเก็บ WebKit

10. อัปเดตเวอร์ชันอย่างไร

ผู้ดูแลเผยแพร่โปรแกรมรุ่นใหม่

เก็บชุด ZIP รุ่นใหม่ใน GitHub แล้วเปิดโครงการเดิมใน Cloudflare → Create a new deployment → Production → อัปโหลดชุด ZIP ให้ครบ → Save and Deploy ห้ามสร้างโครงการหรือเปลี่ยนโดเมนทุกครั้ง ใช้รหัสรุ่นใหม่ทุกครั้งและไม่แก้ไขไฟล์ภายในรหัสรุ่นที่เผยแพร่แล้ว

ตัว POS ตรวจความครบถ้วนด้วยรหัสตรวจไฟล์ ถ้า Cloudflare ยังเผยแพร่ไม่ครบหรือดาวน์โหลดขาด จะไม่ขึ้นว่ารุ่นใหม่พร้อม รอเผยแพร่สำเร็จแล้วตรวจอีกครั้ง การย้อน Deployment บนโฮสต์ไม่ใช่การกู้ฐานข้อมูลใน iPad และไม่ควรใช้แทนขั้นตอนแก้ปัญหาข้อมูล

เจ้าของติดตั้งบน iPad

1. ต่ออินเทอร์เน็ต เข้าด้วยบัญชีเจ้าของ กด ตรวจเวอร์ชันใหม่ ถ้ายังดาวน์โหลดอยู่ รอสักครู่แล้วตรวจอีกครั้ง

2. ปิดกะ ตรวจรายการค้างยืนยันของผู้ใช้ทุกคน และปิดหน้าต่าง POS อื่นให้หมด

3. กด เตรียมอัปเดตเป็น ... ระบบจะตรวจเงื่อนไข สร้างสำเนา และหยุดรับรายการใหม่

4. กด 1. ดาวน์โหลดไฟล์สำรอง ตรวจในแอปไฟล์แล้วเก็บนอกเครื่อง

5. กด 2. ยืนยันสำรองแล้วและอัปเดต หน้าจะโหลดใหม่และให้เข้าสู่ระบบ

6. ตรวจรหัสรุ่น ชื่อร้าน บิลล่าสุด ยอดรายงาน และค่ามือค้างก่อนเปิดกะใหม่

การปิดแล้วเปิดแอปเพียงอย่างเดียวจะไม่เลือกโปรแกรมรุ่นใหม่แทนคุณ หากยังไม่ได้ยืนยันใช้รุ่นใหม่ แอปจะใช้รุ่นที่เลือกไว้เดิม เมื่อมีการเปลี่ยนโครงสร้างฐานข้อมูล ระบบสร้างสำเนาก่อนเริ่มอีกชั้น

หากเปิดรุ่นใหม่แล้วผิดปกติ หยุดขายและเก็บข้อมูลปัจจุบันก่อน ห้ามกู้ไฟล์เก่าโดยไม่ตรวจว่ามีบิลใหม่หลังสำรองหรือไม่ การกู้ไฟล์เก่าทับจะทำให้รายการหลังเวลาสำรองหาย รุ่นนี้ไม่ได้รวมยอดขายหลังสำรองให้เอง

11. ข้อจำกัดที่ต้องรู้

- เป็นฐานข้อมูลของ iPad เครื่องเดียว ไม่มีซิงก์ร้านระหว่างหลายเครื่อง

- GitHub เก็บโปรแกรมและ Cloudflare แจกไฟล์ติดตั้ง ไม่มีระบบสำรองยอดขายออนไลน์ให้เอง

- รุ่นนี้ยังไม่ส่ง Google Sheets, Google Drive หรือ Telegram อัตโนมัติ เมนูที่ยังใช้ไม่ได้ถูกซ่อนหรือปฏิเสธคำสั่งไว้

- ห้ามล้างข้อมูลเว็บไซต์ ลบไอคอน ย้ายโดเมน หรือเปลี่ยน Production URL ของ Cloudflare โดยไม่มีสำเนาและแผนย้ายข้อมูล

- ถ้าเครื่องสูญหายหรือเสีย กู้ได้ถึงข้อมูลในไฟล์สำรองนอกเครื่องล่าสุดเท่านั้น

- ถ้าเปิดแล้วกลับมาหน้าตั้งเจ้าของทั้งที่เคยขายแล้ว ให้หยุดก่อน อาจเปิดผิดลิงก์ ผิดเบราว์เซอร์ หรือพื้นที่เก็บถูกล้าง อย่าตั้งร้านใหม่ทับความเข้าใจว่าข้อมูลเดิมไม่มี

- ถ้าล็อก PIN เพราะใส่ผิด ให้รอตามข้อความ ไม่แก้ด้วยการล้างข้อมูล

12. สิ่งที่ส่งให้ผู้พัฒนาเมื่อมีปัญหา

ระบุรุ่น iPad, iPadOS, ลิงก์ Pages ที่เปิด, รหัสรุ่นที่หน้าจอแสดง, ขั้นตอนก่อนเกิดปัญหา และข้อความผิดพลาด ไม่ส่ง PIN หรือไฟล์สำรองเข้าโพสต์ GitHub สาธารณะ
